# Rainbow

可提交至 Greasy Fork 的 userscript，將 GitHub 倉庫檔案列表中的修改日期標記為越久越深的背景色，並將檔案與資料夾一起依修改時間由新到舊排序。保留原本的日期文字與滑鼠提示。

## 安裝

1. 在瀏覽器安裝 Tampermonkey 或 Violentmonkey 等 userscript 管理器。
2. 新增腳本，將 `github-date-gradient.user.js` 的完整內容貼上並儲存。
3. 開啟 GitHub 倉庫的程式碼列表，點 Star 按鈕旁的「Rainbow」。若頁面沒有顯示 Star，設定入口會暫時放在右上角。彩虹圖示在啟用漸變時顯示彩色，關閉時顯示黑白。

若要發布至 Greasy Fork，建立新腳本並貼上 `.user.js` 內容即可；目前尚未發布。

## 設定與規則

- **單色漸變**：自選主色，從很淺的色調漸變至深色。
- **彩色漸變**：從淺黃經綠色、青色、藍色至深藍，亮度隨日期變舊而降低。
- **啟用漸變**：隨時關閉或重新啟用；設定由 userscript 管理器保存。
- 使用目前可見檔案／資料夾列的 `datetime` 絕對時間，在最舊與最新日期之間線性計算色階。不是依照「幾天前」文字解析。
- 單一日期或所有日期相同時使用中間色；缺少有效日期的列不處理。
- **排序**：順序（舊 → 新）、倒序（新 → 舊）、原序（還原本頁腳本排序前的順序），預設為倒序，選擇會自動儲存。
- 檔案與資料夾混合排序；時間相同時按本頁初始相對順序排列。無有效日期的列、表頭及返回上層連結保留位置。關閉漸變不會關閉排序，選擇「原序」即可還原。
- 自動選擇黑色或白色文字，兼顧淺色及深色 GitHub 主題的可讀性。
- 監聽列表更新、日期載入、視窗大小及 GitHub 頁內導覽；不需要手動重新整理。
- 僅在倉庫根目錄和 `tree` 目錄頁的檔案列生效，不處理提交歷史、Issue、PR 或 README 日期。

腳本不使用外部依賴、不發送網路請求。GitHub 如改變檔案列表的 DOM 結構，可能需要更新選擇器。

## 本機檢查

```sh
node --check github-date-gradient.user.js
node --test tests/date-selection.test.cjs
```

瀏覽器驗收：檢查有多個修改日期的倉庫、子目錄、上一頁／下一頁、兩種顏色模式、自選主色、重新載入後設定保存，以及關閉漸變後恢復原樣。

### 1.0.1 修正

修正網址的倉庫名稱大小寫與頁面連結不同時，全部日期被排除的問題（例如網址 `Stelliberty`、連結 `stelliberty`）。同時避免設定按鈕的可見性更新反覆觸發監聽器。已安裝 1.0.0 的使用者需用新版完整內容取代舊腳本，儲存後重新整理 GitHub。

### 1.1.0 更新

改為日期越久顏色越深，並自動按修改時間由新到舊排列檔案和資料夾。替換舊腳本完整內容、儲存並重新整理頁面即可更新。

### 1.2.0 更新

新增順序、倒序與原序選項，並保存排序偏好。設定按鈕移至 Star 旁邊；找不到可見的 Star 元件時使用右下角入口。

### 1.2.1 修正

Star 定位不再依賴舊版頁首 ID，支援可見文字、星形圖示、Starred 狀態與舊版表單。設定按鈕移出 Shadow DOM，套用 Star 的原生樣式類別、尺寸與外觀屬性，沿用 GitHub 的懸停及主題樣式。若 Star 尚未載入，暫放右上角並在載入後重新定位。

### 1.3.0 更新

腳本、設定面板及按鈕更名為 Rainbow，新增 SVG 彩虹圖示。啟用漸變時圖示為彩色，關閉時為黑白；載入時也會依照已儲存的設定顯示。沿用既有設定儲存鍵。請在原腳本編輯器內取代內容，避免新增一份腳本而重複執行。

### 1.3.1 修正

Rainbow 改用獨立按鈕的四角圓角，不再複製 Star 分組按鈕右側的直角。圓角使用 GitHub 的主題變數，預設為 6px。

### 1.3.3 修正

Rainbow 按鈕改放在 Star 旁的獨立清單項目，並同步處理清單項目的隱藏與移除，避免影響 Star 按鈕的排列。
